# Consuming the platform

Three published repositories — [team-payments](https://github.com/bhavyakeniya/team-payments),
[team-customers](https://github.com/bhavyakeniya/team-customers) and
[team-accounting](https://github.com/bhavyakeniya/team-accounting) — demonstrate
independent team repositories. Mirrors live under `examples/consumers` so this
platform's suite can run without those checkouts. They share all Terraform and
pipeline implementation from this platform.

| Team | Configured buckets per environment | Approved public bucket |
| --- | --- | --- |
| payments | receipts, settlements | None |
| customers | profiles, exports, help-assets | help-assets |
| accounting | ledger, invoices, reports, audit-history | None |

Each project has `team.json` and `environments/dev`, `staging`, `prod`. Each
environment has a v2 `resources.json` explicitly naming the environment and an
`expectations.json`. Change one environment independently; no shared module edit
is needed. `make check` checks all its environments; `make localstack` runs its
actual provider/backend lifecycle against an isolated free Hobby emulator.

```bash
# Platform checkout: check all portable teams (nine environment declarations).
make test-consumers
make test-localstack

# A particular sibling team:
cd ../payments
make check
make localstack
```

A new team is generated by `python -m scripts.onboard`; the team does not write
Terraform or design its CI/CD. The generated thin caller uses the single
`.github/workflows/team-infrastructure.yml` at a reviewed immutable release.
Without a repository and SHA it is generated with a `.template` suffix and does
not run; supplying both activates it. The three published teams are activated
and pinned; the `examples/consumers` mirrors deliberately stay as templates.
There are no copied per-team pipeline implementations.

The shared workflow runs credential-free checks on pull requests and pushes;
`plan` and `apply` are manual dispatches on the default branch only. AWS
catalogs remain disabled fixtures, so a dispatched plan stops at the platform
registration guard until a real account is enrolled. Platform enrollment
supplies backend resources and scoped CI/workload identities; teams do not
provision those themselves. The repositories are published and their checks
run on GitHub; nothing has been deployed to AWS.

Read [environments and delivery](environments-and-delivery.md) for exact JSON,
onboarding commands, CI activation, permissions, per-team S3/DynamoDB state,
environment additions/removal, migration and limitations. Read
[LocalStack](localstack.md) for prerequisites and free-tier evidence boundaries.
Read [team repository tests](team-repo-tests.md) for what each team's checks
verify and how to run them.
